### How the Kitty exit ran (re-runs of failed steps only)
1. **Run 1** passed steps 0–2 up to the payday, then stopped on a race in the script itself. It read the
   inflow row before its memory id was written. The script now waits for both.
2. **`resume … 2`** passed: the payday memory got its blob, and Chi's pull cites it.
3. **`resume … 3`** passed steps 4–7. Step 3 failed, because the Sui SDK's build simulates and refuses to
   build a transaction that would abort.
   - The refusal itself was the chain's (`EExceedsRateLimit` from `0x2::allowance::charge`, through Tatum
     `SimulateTransaction`), but no transaction was sent.
   - The quorum and auto-ok refusals in this run were also caught in simulation (no digest).
4. **The fix:** `chain.run(…, { send: true })` builds the kind alone and sets the gas data in full, so the
   SDK doesn't simulate and the chain records the abort with a digest.
5. **`overcap`** re-ran step 3 on a fresh pot, and **`aborts`** re-ran the two refusals of steps 4–5. All
   three are committed failed transactions (the digests in the table above), and nothing moved.
6. **ADR-0063.** The run showed the memory layer discarding near-identical structured records as
   duplicates: Bao's and Chi's joins, two of three approvals, the suggestion, the pull after payday.
   - Both apps now write without the semantic check.
   - **`suggest`** re-ran step 5's trail: both joins, three approvals and the suggestion are stored, each
     with a blob.
   - Receipts' 16 exit picks were hit the same way: they're anchored onchain, but most of their `PICK`
     memories were discarded before the fix.
