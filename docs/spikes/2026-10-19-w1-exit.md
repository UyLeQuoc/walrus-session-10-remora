## Negative cases (every one refused, with a typed code)

| Case | Where it stops | Code |
|---|---|---|
| Price 0.025 over the Disc's 0.02 per-payment cap | gas station build (simulation) | `simulation_failed:disc.over_per_payment_cap` |
| `payTo` not on the Disc's allowlist | gas station build (simulation) | `simulation_failed:disc.payee_not_allowed` |
| Sponsor daily gas budget used up | gas station ledger | `sponsor.out_of_gas` |
| Paying on mainnet while unavailable | server, before any chain call | `network.unavailable` |

The soft budget (`x402.over_soft_budget`), a wrong signature, the wrong amount, a replay, a non-Disc
payment, a sponsor that's also the funder, use of the gas coin, and a gas budget over the cap are covered
by unit tests (facilitator, signer, merchant).

## Findings

- **Tatum streams `SubscribeCheckpoints` with an `emitModule` filter.** With no match, it sends cursor-only
  frames (about every 25 checkpoints). The stream got one HTTP 429 at start and reconnected. Unary
  pacing doesn't cover streams.
- **The stream starts at the tip.** After a restart the indexer saw a 160-checkpoint gap (more than
  `maxBackfill` = 120) and logged `indexer.gap`. Our own payments still confirm by digest through
  `wake.anchor` jobs.
- **Doomed payments fail at the gas station,** because `tx.build` simulates for the gas budget. The
  facilitator returns the Disc's error code, so the remora never signs anything doomed.
- **Matching types by substring is a trap:** `::disc::Disc` is inside `::disc::DiscKey`. The created
  object of `Field<DiscKey, ID>` (object-owned) got picked as the Disc. Match `name(<|$)`.
- **The full server (`apps/server`) still can't boot locally** because `MEMWAL_ACCOUNT_ID` in `.env` is a
  TODO. The e2e uses the server's money modules directly and serves the money routes over real HTTP.
